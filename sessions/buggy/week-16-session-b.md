# Week 16, Session B: Stop before an obstacle

**Route:** Buggy  
**Time:** About 60 minutes. You may split it across days.  
**Guides:** Use [Teach Computing’s robot buggy unit](https://teachcomputing.org/curriculum/key-stage-4/physical-computing-project) for the lesson goal and [Kitronik’s buggy tutorials](https://kitronik.co.uk/blogs/resources/online-tutorial-autonomous-robotics-platform-for-pico-motors) if using that kit. Follow your kit maker’s wiring and power directions.

## Before starting

- [ ] Complete the [previous session](../buggy/week-16-session-a.md), or repeat it if the checkpoint was difficult.
- [ ] Have ready: Buggy, its distance sensor, cardboard obstacle, ruler, batteries.
- [ ] Parent preparation: Mark two stopping distances on the floor.

## During the session

1. **Recall (5 min):** Look at what you made in Session A and ask what should happen next.
2. **Build or change (40 min):** Add a rule that stops the motors when the distance is below a threshold. Try the obstacle three times at each stopping distance, then change one threshold and compare where the buggy stops.
3. **Check (10 min):** Run, demonstrate or inspect the result. Ask what changed and what stayed the same.
4. **Record (5 min):** Measure each stop with the ruler in cm and write it in a table (threshold, trial, cm). Compare the smallest and largest stop for each threshold. Optional: find the average.

## Finished when

He explains how distance → decision → motor stop works. If this takes longer, stop at a working point and continue next time.

If stuck: Stop and disconnect power. Test one motor or sensor at a time using the kit maker’s instructions.
