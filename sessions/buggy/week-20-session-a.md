# Week 20, Session A: Improve and demonstrate

**Route:** Buggy  
**Time:** About 45 minutes. You may split it across days.  
**Guides:** Use [Teach Computing’s robot buggy unit](https://teachcomputing.org/curriculum/key-stage-4/physical-computing-project) for the lesson goal and [Kitronik: using the motors](https://kitronik.co.uk/blogs/resources/online-tutorial-autonomous-robotics-platform-for-pico-motors), [Kitronik: line-following sensors](https://kitronik.co.uk/blogs/resources/online-tutorial-autonomous-robotics-platform-pico-line-following) or [Kitronik: ultrasonic sensor](https://kitronik.co.uk/blogs/resources/online-tutorial-autonomous-robotics-platform-pico-ultrasonic-sensor) if using that kit. Follow your kit maker’s wiring and power directions.

## Before starting

- [ ] Complete the [previous session](../buggy/week-19-session-b.md), or repeat it if the checkpoint was difficult.
- [ ] Have ready: Working buggy, saved code, same course, notebook.
- [ ] Parent preparation: Read the Week 19 trial notes and identify the most common failure.

## During the session

1. **Warm up (5 min):** Ask what your child remembers from the last session.
2. **Work together (30 min):** Change one part of the code or course layout. Run three trials under the same conditions.
3. **Check understanding (10 min):** Ask: “Did that one change help, and how can we tell?” Let him point to the code, drawing or hardware when answering.

## Finished when

He answers the check question in his own words, and three new trials show what happened after one change. If this takes longer, stop at a working point and continue next time.

If stuck: Stop and disconnect power. Test one motor or sensor at a time using the kit maker’s instructions.
