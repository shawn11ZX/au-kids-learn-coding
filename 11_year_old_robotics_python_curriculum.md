# Python and robotics: a parent-led plan

For an 11-year-old learning with a parent who has a little tech experience. The goal is to write Python, control simple electronics, build a wheeled buggy if he wants to, and eventually program a **SunFounder PiDog V2 with Raspberry Pi 5**. The pace is **two sessions each week**: Session A (about 45 minutes) introduces an idea; Session B (about 60 minutes) lets him change and test it. Repeat or split any session when needed.

## Start here

1. Open [Week 1, Session A](sessions/python/week-01-session-a.md). You need only a computer, a browser and a notebook.
2. Before each session, read its **Before starting** checklist. Open the linked public lesson and put the listed parts on the table.
3. Let your child type, predict, build and explain. Give hints; take over only for power connections, delicate assembly or a safety problem.
4. At the end, use the **Finished when** check. If it is difficult, repeat the session or make the task smaller. The week numbers are a guide.
5. Place orders when the session says to. The [shopping list](#shopping-list) gives the parts for each stage. Check deliveries before the first session that uses them.

If you have one hour a week, do Session A one week and Session B the next. You can stop after the Pico stage, take the buggy route, go directly to PiDog, or do both robots. **Doing both:** finish buggy Week 20, then use the PiDog files labelled Weeks 13–22 as your calendar Weeks 21–30.

## Useful terms and teaching habits

- **Program:** Instructions the computer runs. **Variable:** A named value the program remembers. **Loop:** Instructions repeated several times. **`if` decision:** A rule that chooses what happens next.
- **MicroPython:** Python for a small board such as the Pico. **Firmware:** The software that makes the Pico ready to run MicroPython. **Thonny:** The free editor used to send code to the Pico.
- **Input / sensor:** Something the program reads, such as a button or distance. **Output:** Something it controls, such as a light, buzzer or motor. **Servo:** A motor commanded to a position, used for PiDog’s joints.
- Ask “What do you expect?” before running code. Change one thing, test it, and keep the last working copy. Let your child explain what happened in his own words.
- Unplug the Pico before changing wires. For a buggy or PiDog, disconnect power before changing motor or servo connections. Use the maker’s instructions for wiring, batteries and calibration.

## Public lessons behind the plan

- [Raspberry Pi Foundation: Introduction to Python](https://projects.raspberrypi.org/en/collections/python) and [Introduction to Raspberry Pi Pico](https://projects.raspberrypi.org/en/collections/physical_computing) provide the guided early projects.
- [Teach Computing: physical computing robot buggy](https://teachcomputing.org/curriculum/key-stage-4/physical-computing-project) provides the order of buggy lessons. It is aimed at older students, so the home schedule takes smaller steps.
- [SunFounder: PiDog documentation](https://docs.sunfounder.com/projects/pidog/en/latest/) provides the assembly, setup, servo calibration and Python examples. Follow the printed V2 guide if it differs from a video.
- [Raspberry Pi: Pico 2](https://www.raspberrypi.com/products/raspberry-pi-pico-2/) and [official 27 W power supply](https://www.raspberrypi.com/products/27w-power-supply/) document the recommended boards and desk power supply.

The sequence reflects how school curricula build from simple instructions and decisions toward physical computing. [Queensland Years 5–6 Digital Technologies](https://www.qcaa.qld.edu.au/downloads/aciqv9/technologies/curriculum/ac9_tech_digital_yr5-6_as_cd_alignment.pdf) mainly uses visual programs at this age; text-based Python is an extension for a child who wants it. Finishing a small, dependable robot and explaining how it works is the goal. Advanced topics such as ROS, pathfinding and control theory can wait until he asks for them.
